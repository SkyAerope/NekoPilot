# 截图、附件存储与解码测量

## 存储结构

- 扩展源的 IndexedDB 数据库：`nekopilot-assets`，版本 `1`。
- `assets` 对象仓库保存原始 `Blob`，以 MIME 与内容 SHA-256 组成键，相同文件正文复用同一记录。
- 侧边栏 `chrome.storage.local.chatLogs` 保存 `screenshot` 引用，包括 `id`、`mime`、`size` 和可获取的图片尺寸。
- 后台 `chrome.storage.session.conversationState` 保存 `screenshot` 消息部分，不再嵌入截图 Base64。
- 向模型发送请求时，临时读取 Blob 并物化为提供商支持的 Base64 图片；不会把请求副本写回历史。
- 用户上传的图片和 UTF-8 文本复用同一对象仓库。本地日志保存 `attachments` 描述，会话历史保存 `attachment` 消息部分，均只含名称、类型和文件引用，不含正文。文本在请求副本中解码，图片转换为提供商图片输入。

`prunedFromContext` 仍属于日志引用，而非文件记录。上下文裁剪不删除 UI 可查看的文件。

## 迁移与失败处理

侧边栏恢复旧日志时，先写入截图 Blob，再替换 `screenshotData`、`screenshotMime` 和重复的截图工具结果正文。后台启动时转换带截图标记的旧图片消息。迁移重复执行会复用相同的内容键。

写入以 IndexedDB 事务完成为准，而不是请求成功。迁移失败会保留旧数据；新截图写入失败不会发布引用。截图引用对应的文件缺失时，预览显示失败，模型请求使用不可用提示而非损坏的图片。用户附件缺失或损坏则明确拒绝请求，不用文件名代替正文；重试附件消息先校验文件，再一次性提交历史替换，避免失败时丢失原有对话。

侧边栏迁移和防抖保存带有对话代次检查，清空后的迟到结果不能恢复旧日志。后台截断历史也会阻止旧运行结果恢复已移除的消息。

## 预览生命周期

展开、鼠标移入或键盘聚焦时，读取 Blob、创建文档级 `blob:` URL，再调用 `Image.decode()`。

折叠时保留已解码资源，避免再次展开等待；替换引用、移除条目或卸载组件时清空图片源并撤销 URL。URL 不进入任何持久化记录。

## 当前边界

- 仅旧截图可迁移；旧附件记录只有文件名，不能还原文件内容。新上传支持的格式与大小限制见 README 的附件章节。
- IndexedDB 仍受浏览器配额约束，未新增 `unlimitedStorage` 权限。
- 已实现孤立 Blob 自动回收；不按大小或时间驱逐仍被引用的文件，容量管理仍为后续工作。
- 两类元数据的原有生命周期不变：本地日志跨浏览器重启保留，模型会话历史只跨后台重启保留。

## 孤立文件回收

触发时机：后台每次启动或重新唤醒并恢复历史后、新建对话清空两类引用后，以及截图发布、迁移、保存和内存引用释放后的安全边界。不添加周期定时器或依赖任意时间宽限期。

回收的保留集合包括本地 `chatLogs`、会话 `conversationState` 及打开面板持有的截图和附件引用。准备附件使用独立内存引用锁，批量准备失败时释放已获得的锁，成功时交接给日志后释放。`prunedFromContext` 不影响保留：模型不再使用的图片，只要 UI 仍可查看就不会删除。上传附件不参与截图裁剪。相同内容被多个记录引用时，只要其中一个引用有效就保留。

跨上下文使用同源 Web Locks：发布共享锁覆盖 Blob 写入到引用发布的窗口；回收获取非阻塞排他锁后才读取最新保留集合，忙碌时跳过，在发布结束时补做。侧边栏用逐文件共享锁保护本轮曾引用的截图，直到新建对话或面板销毁，覆盖防抖保存、存储失败和多个面板的内存状态。新建对话不强行回收另一面板仍持有的文件。

元数据写入和清空共用串行屏障，代次检查在屏障内执行。后台等待最终历史保存和截图事件交接完成后才结束发布；历史保存失败时保留未发布历史的内存引用锁，成功保存或新建对话后释放。面板收到文件引用后，先持有内存引用锁再确认交接，避免 React 更新与防抖保存之间出现无保护窗口。

删除只扫描 IndexedDB 的键，不加载图片正文；无引用的记录在一个读写事务中删除，以事务提交为完成依据。读取任一引用存储失败、引用结构损坏或删除事务中止时不执行有效删除；缺少 Web Locks 时跳过自动回收，保守保留文件。没有新增数据库版本、权限或第三方依赖。

## 解码基准

运行方式：

```sh
pnpm build
pnpm exec playwright test --config playwright.benchmark.config.ts --repeat-each 3
```

每种图片每轮预热 5 次，再测量 30 次新 Image、新 Blob URL 的读取与首次解码；另测量保留同一图片资源后再次调用解码的耗时。三轮共 360 个测量样本。原始数据写入 `artifacts/screenshot-decode/**/decode-timings.json`。

测量环境：Windows、Chrome `154.0.8037.93`、AMD Ryzen AI 7 H 350。以下为最终三轮测量的分位数范围，单位为毫秒：

| 图片 | IndexedDB 读取 p95 | 首次解码 p50 | 首次解码 p95 |
|---|---:|---:|---:|
| 文本密集，1440 × 798 | 0.5–0.6 | 3.5–3.7 | 4.0–4.5 |
| 文本密集，1920 × 1080 | 0.5–0.6 | 5.0–5.3 | 5.5–5.8 |
| 高熵压力样本，1920 × 1080 | 1.9–2.0 | 6.5–7.0 | 7.5–8.6 |
| 文本密集，3840 × 2160 | 0.6–0.7 | 20.0–20.5 | 23.5–24.5 |

保留资源再次解码的 p95 为约 0.1–0.3ms。

这些数据不代表磁盘冷启动，也不直接等价于最终绘制时间。文本密集样本是确定性合成图片，高熵样本用于压力测试，不宣称覆盖所有真实网页或设备。

**当前决定：保留 hover/focus 预解码。** 默认尺寸的解码较快，但 4K 图片仍超过一个 60Hz 帧预算；仅凭当前存储与解码数据不足以证明移除预热不会增加首次展开等待。

```sh
pnpm exec playwright test tests/ui/asset-gc.spec.ts tests/ui/asset-storage.spec.ts tests/ui/screenshot-storage.spec.ts tests/ui/screenshot-motion.spec.ts tests/ui/screenshot.spec.ts

```

真实扩展测试默认使用已安装的 Edge，可用 `EXTENSION_CHANNEL` 选择支持 CDP 扩展加载的浏览器通道。测试使用独立临时 Profile，验证两个提供商的请求、后台与侧边栏共享 Blob、后台重启时保留有效引用并删除注入的孤立文件、重新打开后的预览，以及新建对话后的文件回收。
